# LinkLogic: real-time entity resolution for corporate registry records

One company is written differently in every registry. "Tata Motors Limited", "TATA MOTORS LTD." and
"Tata Motor Limited" name one legal entity, but a join on the name string treats them as three. This
project links each arriving record to a golden entity, merges only on strong evidence, and sends
doubtful cases to a review queue.

Course project for an AWS evaluation brief (Team LinkLogic: Modassir Ahmad, Parnika Kumar, VIT Vellore).
The written report, with the architecture diagrams and the cost analysis, is submitted separately.

## What is here

| Path | What it does |
| --- | --- |
| `data/fetch_gleif.py` | Pulls a sample of entities from the public GLEIF LEI API |
| `data/build_dataset.py` | Builds 7,780 records from 5,200 entities with registry-like noise: suffix swaps, case and punctuation changes, typos, a leading "THE", a dropped word, and GLEIF `otherNames` as aliases |
| `data/records.csv`, `data/aliases.csv` | The generated dataset; the source LEI is kept as `truth_group` for scoring |
| `sql/01_schema.sql` | Tables, trigram and partial indexes, `normalize_name()`, `digit_tokens()`, audit trigger |
| `sql/02_resolver.sql` | `resolve_record()`: block, score, decide, link, under a per-block advisory lock |
| `sql/03_load_and_run.sql`, `sql/run_experiments.sh` | Load the data and sweep the auto-merge threshold |
| `sql/04_evaluate.sql` | Pairwise precision, recall, F0.5, decision counts, latency |
| `sql/06_concurrency.sh` | Eight workers against 400 near-duplicate pairs, with and without the lock |
| `sql/07_tata_case.sql`, `sql/08_scale_test.sql` | Worked example; GIN index behaviour at 500,000 rows |
| `lambda/lambda_function.py` | The AWS worker: normalise, embed with Bedrock Titan Text Embeddings V2, write to or query an Amazon S3 Vectors index. Handles a console test event or an SQS batch |
| `iam/lambda_extra_permissions.json` | The inline policy for the function: one model, one vector index, one queue |
| `results/*.txt` | Raw output behind every number quoted in the report |

## How resolution works

For each arriving record: normalise the name (lower case; punctuation and legal words such as `ltd`,
`gmbh` and `the` removed), take up to ten same-country candidates sharing trigrams (GIN index over
records and aliases), skip any candidate whose digit tokens differ, then decide.

| Condition | Decision |
| --- | --- |
| score >= 0.75 and (score >= 0.90 or equal postcode) | merge into the candidate's entity |
| score >= 0.55 but no merge | new entity plus a review row |
| no candidate >= 0.55 | new entity |

A transaction-scoped advisory lock on `country + first token` serialises each block, and the SQS FIFO
message group uses that same key, so ordering in transit and locking at rest enforce one rule.

## Results on 7,780 records from 5,200 real GLEIF entities

| Auto-merge threshold | Aliases | Precision | Recall | F0.5 | Reviews |
| --- | --- | --- | --- | --- | --- |
| 0.60 | on | 0.8974 | 0.8539 | 0.8883 | 636 |
| 0.75 (default) | on | 0.9759 | 0.7845 | 0.9305 | 864 |
| 0.75 | off | 0.9755 | 0.7702 | 0.9261 | 857 |
| 0.85 | on | 0.9853 | 0.7260 | 0.9196 | 1,029 |
| 0.95 | on | 0.9937 | 0.6775 | 0.9089 | 1,162 |

Resolution took 4.65 ms per record on average (7.37 ms p95). With eight concurrent workers, 400
near-duplicate pairs produced 380 duplicate entities without the advisory lock and none with it.

The noise is generated by `build_dataset.py`, so these scores measure robustness to those
perturbations, not accuracy on real discrepancies between two independent registries.

## Running it

```bash
# PostgreSQL 17 with the pg_trgm and pgvector extensions
createdb linklogic
psql -d linklogic -f sql/01_schema.sql
psql -d linklogic -f sql/02_resolver.sql
python3 data/fetch_gleif.py && python3 data/build_dataset.py
cd sql && ./run_experiments.sh
```

The Lambda function needs the inline policy in `iam/`, a Bedrock model id for Titan Text Embeddings V2,
and an S3 Vectors index of 256 dimensions using cosine distance.

## Note on the AWS account

The AWS account id is masked as `<account-id>` in this repository. Bucket, index and queue ARNs need
your own account id to run.
